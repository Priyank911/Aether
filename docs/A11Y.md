# Phase 4 accessibility evidence

Date: 2026-11-20. Task 4.10 is **partial**, not an accessibility sign-off.

## Automated checks completed

- `apps/desktop/tests/a11y.e2e.test.ts` drives a real Electron window with
  native keyboard events and no pointer input. A live Code Mode question
  opens its decision card and focuses Send answer. F6 reaches the omnibox;
  Tab reaches Activity; Left/Right switch Activity and Memory. Shift+Tab
  reaches the answer field, typing and Enter resolve the held script with
  the actual answer, and Ctrl+Backslash closes the panel.
- The same test checks the complementary landmark, dialog role and valid
  heading relationship. These assertions do not measure spoken output.
- `scripts/check-contrast.mts` checks 24 token/threshold pairs across the
  light and dark themes as part of `pnpm test`. This is token coverage,
  not a whole-interface WCAG audit.
- Panel and overlay fixture suites additionally exercise real approval,
  denial, questions, resize geometry, Escape takeover and Find behavior.
  They are not substitutes for a screen-reader pass.

Validation: `pnpm typecheck`, `pnpm lint` (0 errors, 7 existing warnings),
and the single-fork full suite passed: 44 files / 312 tests, without retries.
However, the latest repeat failed this test's initial-focus check: active
element text stayed empty instead of Send answer (311 passed / 1 failed).
This is unresolved; the keyboard flow is not consistently verified. No two
consecutive passing exit runs are claimed. See `AUDIT.md` for all reruns.

## Manual Windows acceptance — not run

NVDA was **not run**. No auditory announcement quality, manual keyboard
acceptance or full WCAG 2.2 AA conformance is claimed. Offscreen fixture
input cannot establish what a person hears in the Windows accessibility
stack. Do not enable a screen reader or use personal sign-ins implicitly.

Run these checks with a person using NVDA and record its version, Windows
version, app revision, result and any issue for each item:

- [ ] Start in Personal. Reach the omnibox, tab strip, Space switcher,
  toolbar and side panel using only the keyboard. Names, selected states
  and focus indicators are clear; the person can leave every control.
- [ ] Open a free-text question. Focus moves to the primary action; NVDA
  reads the title, question and unavailable-until-answered state correctly.
  Reach the labeled field, answer and submit without a pointer.
- [ ] Repeat with an options question. The group legend, option names,
  selection and arrow-key navigation are usable.
- [ ] Review an irreversible approval, values and Deny. Both outcomes
  resolve the held run; secrets remain masked. Review every URL in a batch.
- [ ] Wait on a pending request: the waiting update is announced once,
  not repeatedly as elapsed time or milestones change.
- [ ] Escape takes over an acting Agent Space. Reach the page and then
  Hand back to Aether. Background requests do not steal Personal focus.
- [ ] Tab and Shift+Tab leave the decision card: no dialog focus trap.
  Switch Activity/Memory using arrows and resize using the separator's
  arrows/Home/End; confirm names and values are announced.
- [ ] Find next/previous and Escape work from a page with keyboard focus.
  Menus close with Escape and outside clicks without leaving a focus trap.
- [ ] At 1280 px window width and 200% shell zoom, no horizontal shell
  scrolling or inaccessible controls; cards remain readable and operable.
- [ ] With reduced motion enabled, pulse and cursor glide stop. Both light
  and dark themes retain visible focus, legible text and non-color states.
